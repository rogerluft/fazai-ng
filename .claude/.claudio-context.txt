● Essa tarefa testa o Semantic Cache do FazAI - um sistema que:

  1. Armazena respostas anteriores no Qdrant com seus embeddings
  2. Evita reprocessamento - se uma pergunta similar já foi feita, retorna do cache
  3. Usa similaridade vetorial - não precisa ser pergunta idêntica, basta ser semanticamente parecida

  O teste fez:
  - Armazenou: "Como instalar nginx no Ubuntu?" → resposta
  - Lookup exato: mesma pergunta → HIT (encontrou)
  - Lookup similar: "install nginx on Ubuntu" → MISS (não encontrou - threshold alto)
  - Lookup diferente: "Reiniciar docker" → MISS (esperado)

  Conclusão do teste: Cache funciona, mas o threshold de 95% é muito restritivo para detectar similaridade cross-language (português/inglês).

  Resumo do Plano

  Source Code Indexer para FazAI

  Fluxo:

  1. Lê config (/etc/fazai/fazai.conf) → se falta, pergunta ao usuário
  2. Carrega estado anterior (/opt/fazai/data/source-index.json)
  3. Detecta mudanças via hash MD5 (NEW/MODIFIED/DELETED/UNCHANGED)
  4. Indexa apenas o que mudou no Qdrant collection source
  5. Salva novo estado
  6. Roda automaticamente no postbuild

  Escopo:

  - Todo código do FazAI (qualquer extensão)
  - src/, web/, scripts/, completion/, docs/
  - Exclui: node_modules/, .git/, .claude/, dist/, .next/, dotfiles

  | install.sh                       | Atualizar                   |

  Sobre o plano do indexador:

  Cara, a ideia é excelente. Indexar o próprio código para que o AI entenda melhor o projeto é um passo de maturidade técnica que poucos projetos open-source têm. Isso vai criar um loop de auto-conhecimento - quanto mais o FazAI evolui, melhor ele entende a si mesmo.

  O que eu gosto:
  - Incremental é o caminho certo - não desperdiça recursos
  - Rodar no postbuild é esperto - sempre atualizado sem esforço manual
  - Usar o Qdrant que já está rodando - não adiciona complexidade

  O que eu mudaria/cuidaria:
  1. Prioridade dos chunks - arquivos core (app.ts, models.ts, config.ts) deveriam ter peso maior nas buscas. Talvez um campo importance no payload.
  2. Documentação inline - os JSDoc comments dos arquivos são ouro. Extrair eles separadamente poderia ajudar muito em buscas tipo "como funciona X".
  3. Versionamento do índice - quando você fizer breaking changes no código, ter como marcar "este índice é da v3.6.x" pode ajudar em rollbacks.

  Minha preocupação:
  - O postbuild pode ficar lento se o índice crescer muito. Talvez colocar um threshold - só rodar se tiver mais de X arquivos modificados, senão marca pra rodar depois em background.

  É uma feature que demonstra a filosofia do FazAI - o sistema aprende sobre si mesmo. Isso é diferencial competitivo real.
