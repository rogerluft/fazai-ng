# Fluxo do Indexador de Código Assíncrono (Metacognição FazAI)

## 1. O Gatilho (Assíncrono)
O processo é iniciado por um daemon que não interfere na operação normal do FazAI.

- **Serviço Systemd:** `fazai-worker.service` é ativado no boot do sistema.
- **File Watcher (`chokidar`):** Este serviço lança um processo Node.js que "escuta" os diretórios do projeto (`src/`, `docs/`, `scripts/`).
- **Evento de Mudança:** Ao salvar um arquivo (`git pull`, edição manual), o `chokidar` detecta a alteração e aciona o indexador, passando o caminho do arquivo modificado.

```ascii
[Usuário/Git salva um arquivo] ----> [Sistema de Arquivos do Linux]
        |
        v
[Daemon: chokidar "ouve" a mudança] ----> [Dispara o Indexador]
```

## 2. A Lógica (Incremental e Inteligente)
O indexador evita reprocessar o projeto inteiro, focando apenas no que mudou.

1.  **Carregar Estado Anterior:** O indexador lê um arquivo de manifesto (ex: `.claude/state/source-index.json`) que contém o hash de cada arquivo já processado: `{"src/app.ts": "hash123"}`.

2.  **Calcular Hash Atual:** Ele calcula o hash MD5 ou SHA256 do conteúdo do arquivo modificado.

3.  **Comparar e Decidir:**
    *   **Hash Igual:** O conteúdo não mudou. O processo para aqui.
    *   **Hash Diferente ou Arquivo Novo:** O arquivo precisa ser re-indexado.

4.  **Chunking Semântico (AST Parser):**
    *   O código do arquivo não é indexado como um bloco único.
    *   Um **Abstract Syntax Tree (AST) parser** é usado para "ler" a estrutura do código e dividi-lo em pedaços lógicos e coesos: `funções`, `classes`, `métodos`. Cada um desses pedaços se torna um "documento" a ser indexado.

5.  **Vetorização (Lei 1536):**
    *   Cada "chunk" de código é passado para o **Universal Local Embedder**.
    *   O embedder chama o Ollama (`nomic-embed-text`, 768d).
    *   O resultado passa pelo **Adapter de Zero Padding**, expandindo o vetor para **1536 dimensões**.

6.  **Atualizar Qdrant (`upsert`):**
    *   O comando `upsert` é usado para inserir/atualizar os dados no Qdrant na collection `source`.
    *   O `id` de cada ponto é um identificador único derivado do caminho do arquivo e do nome do símbolo (ex: `hash("src/app.ts:main")`). Isso garante que, ao re-indexar um arquivo, as funções modificadas sejam atualizadas em vez de duplicadas.

## 3. A Memória (Payload na Collection `source`)
Cada ponto na `source` collection armazena metadados ricos para dar contexto à IA:

```json
{
  "id": "hash_do_caminho_e_funcao",
  "vector": "[...vetor de 1536 dimensões...]",
  "payload": {
    "content": "async function main() { ... }",
    "file_path": "src/app.ts",
    "symbol_name": "main",
    "symbol_type": "function",
    "start_line": 25,
    "end_line": 80,
    "content_hash": "hash_do_conteudo_da_funcao",
    "last_indexed": "2025-12-27T18:00:00Z"
  }
}
```

Este processo garante que o FazAI tenha uma compreensão sempre atualizada de sua própria estrutura interna, permitindo que ele raciocine sobre seu código de forma autônoma.
