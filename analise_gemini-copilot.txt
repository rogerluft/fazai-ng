RELATÓRIO DE ANÁLISE TÉCNICA: FAZAI-NG
========================================
Data: 2025-12-12
Gerado por: Gemini/Copilot CLI

1. VISÃO GERAL DO PROJETO
-------------------------
Nome: FazAI (fazai-ng)
Versão: 3.4.2-beta (baseado no package.json/logs)
Propósito: Assistente CLI inteligente para administração Linux que traduz linguagem natural em comandos, com execução segura e capacidades agênticas.
Stack Principal: Node.js, TypeScript, Next.js (Web), Qdrant (Vector DB).

2. ESTRUTURA DE DIRETÓRIOS
--------------------------
/src
  /agentic       - Lógica de agentes (DAG executor, decompositor de tarefas)
  /commands      - Implementação dos comandos CLI (github, cloudflare, sync)
  /config        - Gerenciamento de configuração e timeouts
  /database      - Conexão com Qdrant (memória vetorial)
  /mcp           - Implementação do Model Context Protocol (Client/Server)
  /services      - Serviços de embeddings e cache
  /utils         - Utilitários gerais (retry, batch processing)
  /web           - Interface Web (Next.js Dashboard)
  app.ts         - Ponto de entrada da CLI
  linux-admin.ts - Core da tradução NL -> Comando
  linux-executor.ts - Executor seguro de comandos

/web             - Aplicação Next.js para dashboard e visualização
/scripts         - Scripts de deploy, setup de ambiente e manutenção
/tests           - Testes unitários e de integração (Vitest)
/docs            - Documentação extensiva (Architecture, Agents, Manual)

3. ARQUITETURA E COMPONENTES CHAVE
----------------------------------
A. CLI & Core Logic
   - O `src/app.ts` orquestra a CLI usando `commander` (provável, baseado na estrutura).
   - `src/linux-admin.ts` atua como a ponte principal para os LLMs, gerenciando prompts e respostas.
   - `src/linux-executor.ts` garante a execução segura dos comandos gerados.

B. Inteligência Artificial & Agentes
   - Suporte Multi-LLM: Ollama (local), OpenRouter, Anthropic.
   - Agentes: Implementação em `src/agentic/` sugere capacidade de quebrar tarefas complexas em passos (DAG - Directed Acyclic Graph).
   - Memória: Uso de Qdrant (`src/vector-store.ts`) para RAG (Retrieval-Augmented Generation) e contexto de longo prazo.

C. Configuração (`src/config.ts`)
   - Sistema hierárquico robusto:
     1. /etc/fazai/fazai.conf (Sistema)
     2. CWD/fazai.conf (Local override)
     3. ~/.config/fazai/fazai.conf (Usuário)
   - Variáveis de ambiente suportadas.

D. Interface Web (`/web`)
   - Dashboard moderno construído com Next.js, Tailwind CSS e componentes UI (shadcn/ui provável).
   - Integração com a mesma base de conhecimento/memória.

6. SUGESTÕES DE MELHORIA E INSIGHTS (GEMINI/COPILOT)
----------------------------------------------------

A. Limpeza e Higiene do Código (Code Hygiene)
   - [CRÍTICO] Arquivos de Backup no Source Control:
     Detectados arquivos como `src/linux-admin.ts.backup`, `src/linux-admin.ts.backup-1763915205`, etc.
     Recomendação: Remover imediatamente do repositório e adicionar `*.backup` e `*.bak` ao `.gitignore`. Isso polui o histórico e pode causar confusão na importação de módulos.
   - [IMPORTANTE] Gerenciadores de Pacote Mistos:
     Presença de `bun.lockb` e `package-lock.json`.
     Recomendação: Padronizar o uso. Se o projeto usa `npm` (como indicado no CLAUDE.md), remova o `bun.lockb` para evitar "dependency drift". Se migrar para Bun, remova o `package-lock.json`.

B. Arquitetura e Frameworks
   - Validação de Configuração:
     O `src/config.ts` faz parsing manual de arquivos `.conf`.
     Sugestão: Adotar `Zod` para validação de schema da configuração em tempo de execução. Isso previne erros silenciosos se uma chave obrigatória estiver faltando ou mal formatada.
   - CLI Framework:
     Considerando a complexidade crescente (agentes, plugins), avaliar migração de `commander` (se usado) para `Oclif`. Oclif oferece estrutura nativa para plugins e hooks, o que facilitaria a arquitetura modular planejada.
   - Monorepo Tooling:
     Com a adição da pasta `web/` (Next.js), o projeto virou um monorepo implícito.
     Sugestão: Configurar `npm workspaces` no `package.json` raiz para gerenciar dependências compartilhadas e scripts de build unificados (ex: `npm run build` na raiz constrói CLI e Web).

C. Segurança e "Zero Trust"
   - Sandbox de Execução:
     Para o modo "Autonomous" ou "Agentic", apenas validar o comando não é suficiente.
     Sugestão: Implementar um container Docker efêmero ou usar `systemd-run --scope` para isolar a execução de comandos perigosos gerados pela IA, limitando acesso a rede/disco.
   - Secret Management:
     Verificar se chaves de API (OpenRouter, Anthropic) estão sendo sanitizadas nos logs. O `src/logger.ts` deve ter um filtro ativo para regex de chaves conhecidas (sk-...).

D. Performance e UX
   - Cache de Embeddings:
     O `src/services/embedding-cache.ts` é um bom começo.
     Sugestão: Persistir esse cache localmente (SQLite ou JSON simples) além da memória, para que o "warm-up" da CLI seja instantâneo entre sessões.
   - Feedback Visual:
     Para operações longas (RAG search, Agent thinking), usar `ora` ou `ink` para spinners interativos que mostrem o "pensamento" do agente em tempo real, melhorando a percepção de latência.

E. Bugs Potenciais
   - Race Conditions no Config:
     A função `writeConfigLines` em `src/config.ts` lê e escreve o arquivo inteiro. Em um ambiente com múltiplos agentes/processos rodando (CLI + Web + Background Jobs), isso pode causar perda de dados.
     Correção: Usar um lock file ou operações atômicas de escrita.
